# 顔（生き物のデザイン）の作り方

**TOML を 1 ファイル置くだけで顔が増える。Rust は要らない。**

> **手で書く前に `make config` の「キャラクター」を試すのも手。** パーツ（顔のライン・目・
> 髪・鼻・口を各 30 種）を選んで組み合わせると、ここで説明しているのと同じ
> TOML が出てくる。それを土台にして手で数値を詰められる。
> ビルダーのパーツを増やしたいときは **§9**。

- **組込みの顔** … このディレクトリの `*.toml`（`egg` / `round` / `squircle` / `bean`）
- **自分だけの顔** … `~/.config/ccsessions/faces/*.toml` に置く。**再ビルド不要**で、
  走っている `ccsessionsd` が数百 ms で拾い、設定画面の選択肢にも出る

まずは雛形をコピーするのが早い:

```sh
mkdir -p ~/.config/ccsessions/faces
cp faces/_template.toml ~/.config/ccsessions/faces/mine.toml
$EDITOR ~/.config/ccsessions/faces/mine.toml   # id を "mine" に変える
ccsessions face check mine                     # 検証
ccsessions face render mine --size dock > /tmp/mine.svg   # 目で見る
```

---

## 1. 座標系 — 0..1 の比率・左下原点・**y は上向き**

輪郭・目の多角形・パネル線の座標は、すべて**体の矩形に対する 0..1 の比率**。
原点は**左下**で、**y は上へ増える**（CALayer と同じ）。

```
 (0,1) ┌───────────┐ (1,1)      y
       │           │            ↑
       │           │            │
 (0,0) └───────────┘ (1,0)      └──→ x
```

> **CSS や SVG からデザインを写すときは y を反転する。** あちらは y が下向き。
> `0.2` と書きたくなったら `0.8` が正しい、という取り違えがいちばん多い。

pt（絶対値）で書くのは `size` / `gap` / `radius` / `corners_pt` / 目の `size` だけ。

## 2. `half = true` — 右半分だけ書けばよい

`kind = "path"` の輪郭は、`half = true` にすると**右半分だけ**書けば済む。
左半分は `u → 1-u` の鏡像で自動生成され、**左右対称であることがテストで保証される**。

- `d` は `M 0.5 0`（下端の中央）から始め、`0.5 1.0`（上端の中央）で終える
- 折り返し点が中央でないと `symmetry` が落ちる

手で左右を書くと必ず微妙にずれるので、対称な顔は `half = true` にすること。

## 3. bar の体の高さは **22pt 以下**（なるべく 21pt 以下）

メニューバーの高さは**機種依存**で、ここが顔の設計をいちばん強く縛る。

| 画面 | メニューバー高 |
|---|---|
| ノッチのある MacBook（内蔵） | **33pt** |
| 非ノッチ（外部モニタ・Air・旧機種） | **24pt** |

`ccsessionsd` は帯の高さをメニューバー高に収める（超えるとその矩形ぶん、
メニューバー下のクリックを奪ってしまう）。そのため:

- **バリデータの上限は `size.bar.h <= 22`** — 24pt の画面で、上下の余裕 2pt を引いた値。
  これを超えると**体そのものが縮められて**生き物が小さくなる
- **21pt 以下が安全** — ノッチ機（33pt）ではグリフ用に 12pt が体の上に載るので、
  `21 + 12 = 33` がちょうど上限。22pt にするとノッチ機ではグリフが体に重なる段階に落ちる
  （壊れはしないが、見た目が 20pt の顔と変わる）

**組込みの顔はすべて `h = 20`。** 迷ったら 20 にしておけばよい。

`ccsessions face check` はこの制約を数値と理由つきで教えてくれる。

## 4. 状態ごとに表現する（形は目で、色は `[colors.*]` で）

アニメ（揺れる・跳ねる・漂う）とグリフ（`›` `!` `⋯` `z` `✓` `×`）は**全部の顔で
共通**で、顔ごとには変えられない。

守りたい一線は「色を変えられないこと」ではなく**「生き物を見れば状態が分かること」**。
なので色は**状態ごとになら**変えてよく、全状態に一律で効く指定は用意していない
（1 色で 6 状態を塗り潰すと、生き物を見ても状態が読めなくなる）。

```toml
# 書いた状態・書いた色だけが上書きされる。省略はぜんぶ既定パレット。
[colors.working]
accent = "#7f3ac2"   # 枠・グロー・状態記号・バッジ・名前・ホバーカードの縁
fill   = "#241038"   # 体の面の塗り
eye    = "#00ff88"   # 目

[colors.error]
accent = "#ff0044"   # 1 色だけ書いてもよい（面と目は既定のまま）
```

**組込みの顔はどれも `[colors.*]` を 1 行も書いていない。** 書かなければ
下の既定パレット（シアン＝作業中、琥珀＝判断待ち…）で描かれる。

`accent` は生き物の外側ぜんぶに効くので、**6 状態が互いに見分けられる色を選ぶこと**。
状態ごとに別々の色を選ばせているのはそのためで、検証器はここを見ない
（色の良し悪しは機械では決められない）。

`[colors.*]` は**形に一切触らない**。目の色を変えたいだけなら `[eyes.states.*]` では
なくこちらを使う — あちらは書くと既定ルールを丸ごと置き換えるので、瞬きや横目が
消えてしまう。両方に目の色を書いた場合は `[colors.*]` が勝つ。

形のほうは、顔が状態を表現できるのは
**`[eyes.states.*]`（目の形・開き具合・向き・色）だけ**。
しかも**書かなくてよい** — 省略すると既定ルールが全 6 状態を埋めてくれる:

| 状態 | `shape = "rounded"` の既定 | `shape = "polygon"` の既定 |
|---|---|---|
| `working` | 基準 + 瞬き | 基準 + 瞬き |
| `wait_user` | **正円に見開く** + 白 + 滲み | 縦に 1.45 倍 + 白 + 滲み |
| `wait_agent` | 横目（右へ 1.5pt） | 同左 |
| `idle` | 高さ 2pt の横線 + 暗い色 | 縦に 0.4 倍 + 暗い色 |
| `done` | 基準 | 基準 |
| `error` | 赤い目 | 赤い目 |

**組込みの顔はどれも `[eyes.states.*]` を 1 行も書いていない。**
シルエットだけ描けば全 6 状態が成立する。

上書きが要るのは「既定だと自分の顔では成立しない」ときだけ。例えばスリット目は
0.4 倍まで絞ると bar（実寸 1.2pt）で消えるので、`idle` だけ 0.55 に緩める。

## 5. bar では線を間引く

`[[details]]`（顔のパネル線）は `sizes` でどの配置に描くか選べる。

**bar は狭い（18×20pt）。ここに 7 本引くと線が潰れて塊になり、
シルエットと目という「一目で読める部分」まで濁る。** 実測した結果、
線画を持つ顔は bar を眉と口の 2 本程度に落とすのが目安。

`bar-details-not-thinned` が「bar の本数 <= dock の本数」を課す。

## 6. 検証とプレビュー

```sh
ccsessions face list                                  # 使える顔の一覧
ccsessions face check                                 # 全部を検証
ccsessions face check mine                            # id を指定
ccsessions face check ~/.config/ccsessions/faces/mine.toml   # ファイルを指定
ccsessions face render mine --state wait_user --size dock > /tmp/x.svg
ccsessions face gallery > /tmp/gallery.html           # 全顔 × 全状態 × bar/dock
```

`check` は問題を `[eyes-outside-body] bar/working で目が顔からはみ出します…` の形で
返す。**名前が規則そのもので、メッセージに直し方が入っている**ので、ここに一覧は置かない
（一覧と実装の二重管理になり、必ず片方が腐る）。規則の全体を眺めたいときは
`ccsessions-core/src/face/spec.rs` の `ProblemCode` を読むこと — バリアントの doc comment が
定義で、中身は `validate.rs` が実装している。

`notch-width` だけは警告で、`check` は exit 0 のまま。幅が入らなくても
`bar_align = "auto"` がノッチの左へ逃がすので壊れない（組込みの `bean` が実際にそう動く）。

**SVG は CALayer の忠実なプレビュー** — 輪郭・目・線画は daemon が描くのと
完全に同じデータ・同じ計算から出ている。違うのはグローとアニメだけで、
そこは SVG では静止画に近似される。**Mac が無くても顔は作れる。**

## 7. PR の出し方

1. `faces/<id>.toml` を 1 ファイル追加する（他のファイルは触らなくてよい）
2. `ccsessions face check <id>` が通ることを確かめる
3. `ccsessions face render <id> --size dock` の SVG を PR に貼る（レビューが目で見られる）

`cargo test` の `every_builtin_face_passes_validation` が組込み顔を全部ループするので、
置いただけで CI がはみ出しや高さ超過を指摘してくれる。

## 8. スキーマ早見表

```toml
id       = "mine"          # 必須。[a-z0-9-]+、先頭は英数字、32 文字以内
label    = "わたしの顔"     # 必須。設定画面に出る名前
label_en = "Mine"          # 任意
author   = "your-name"     # 任意。ギャラリーのクレジット

[size]                     # pt
bar  = { w = 22, h = 20 }  # h は 22 以下（§3）
dock = { w = 36, h = 34 }

[outline]
kind = "corners"           # "corners" | "capsule" | "path"

# kind = "corners": CSS の border-radius と同じ順（左上・右上・右下・左下）
#   corners    … [水平比率, 垂直比率]。体の寸法に対する割合
#   corners_pt … pt 固定（bar と dock で角丸の見た目を揃えたいとき）
corners = [[0.50, 0.58], [0.50, 0.58], [0.48, 0.42], [0.48, 0.42]]
# corners_pt = { bar = 7.0, dock = 10.0 }

# kind = "capsule": 左右が半円。角丸は自動で h/2（bean がこれ）
# kind = "path":    自由なシルエット。下記参照

[eyes]
shape  = "rounded"                              # "rounded" | "polygon"
v      = 0.5                                    # 顔の中での縦位置（0.5 = 中央）
gap    = { bar = 3.0, dock = 5.0 }              # 両目の間隔（pt）
size   = { bar = [3.0, 4.0], dock = [4.0, 6.0] }  # 基準の [w, h]（pt）
radius = 2.0                                    # rounded のときの角丸（pt）
# polygon = [[0,0],[0,0.62],[1,1],[0.94,0.38]]  # polygon のとき（目の矩形に対する 0..1）

# 目の形の状態ごとの上書き。**書かなければ §4 の既定ルール**
# [eyes.states.idle]
# h_scale = 0.55
# color   = "eye_closed"     # "eye" | "eye_closed" | "eye_error" | "white"

# 色の状態ごとの上書き（任意）。書いた状態・書いた色だけが変わる（§4）
# [colors.working]
# accent = "#7f3ac2"         # 枠・グロー・記号・バッジ・名前・カードの縁
# fill   = "#241038"         # 面の塗り
# eye    = "#00ff88"         # 目（[eyes.states.*].color より優先）

# パネル線（任意）。開いた折れ線。座標は 0..1 比率
# [[details]]
# name   = "brow"
# sizes  = ["bar", "dock"]   # 省略すると両方
# points = [[0.19, 0.725], [0.50, 0.775], [0.81, 0.725]]
```

### `kind = "path"` の `d`

SVG の `d` 属性の**サブセット**。ベクタツール（Illustrator / Figma など）から
書き出したパスを 0..1 に正規化して貼れる。

| 命令 | 意味 |
|---|---|
| `M x y` | 始点へ移動（**先頭に 1 回だけ**） |
| `L x y` | 直線 |
| `C x1 y1 x2 y2 x y` | 3 次ベジェ |
| `Z` | 閉じる（任意。`half = true` なら書かない） |

- **絶対座標だけ。** 小文字（相対座標）はエラーになる
- `A`（円弧）/ `Q` / `S` / `T` / `H` / `V` は未対応 — ベクタツール側で 3 次ベジェに変換する
- 区切りは空白・改行・カンマのどれでもよい

```toml
[outline]
kind = "path"
half = true
d = """
M 0.500 0.000
L 0.615 0.000
C 0.700 0.020 0.770 0.075 0.815 0.170
C 0.960 0.890 0.795 1.000 0.500 1.000
"""
```

## 9. ビルダーにパーツを足す

`make config` のキャラクタービルダーが並べるパーツは、
**`ccsessions-core/src/face/builder/parts.rs` の表 1 つが唯一の定義**。
画面はこの表を `/api/parts` 経由で列挙して描くので、**HTML も JS も触らなくてよい**。

### バリエーションを 1 つ足す

該当する表に**行を 1 つ**足して `make check`。それだけ。

```rust
// 髪（HAIR）。Curve は 弧 / 波 / 流し / への字 / かぎ形 / 輪 / 点
//                     ＋ 板 / 門型 / 縦棒 / 角波 から選ぶ。
//    id            表示名          素形            v(高さ) w(幅) amp(振れ)
line("bob-short",  "ショートボブ",   Curve::Arc,     0.72,  0.90, 0.060),
line("spike6",     "とげ 6",        Curve::Wave(6), 0.74,  0.88, 0.085),

// 目（EYES）。まぶた 2 本（目頭の高さ・目尻の高さ・上のふくらみ・下のふくらみ）。
//       id          表示名     w    h   gap  inner outer upper lower
lid_eye("sleepy",  "ねむたげ", 4.4, 2.6, 2.8, 0.55, 0.45, 0.12, 0.40),

// 顔のライン（FACES）。半幅を あご→頬→こめかみ→冠 の 4 つで決める。
//   id        表示名    幅   目のv  あご  あご幅 頬    こめかみ 冠
sil("gourd", "ひょうたん", 22.0, 0.54, 0.02, 0.22, 0.40, 0.46, 0.30),
```

数値の意味は各 struct の doc comment にある。**幅（`w`）は体幅ではなく
「その高さで顔がどれだけ広いか」に対する比率**なので、細あごの顔に載せても
自動的に小さくなる。

### 左右 1 対のパーツを足す

耳・頬のパネル・ひげのように**左右に 1 つずつ**置くものは `pair(...)` を使う。
`[[details]]` が `<カテゴリ>-r` / `<カテゴリ>-l` の 2 本になり、
左は右の鏡像なので**左右対称は自動**（片側だけずれる書き間違いが起きない）。

```rust
//    id          表示名     素形                         v    off(端寄せ) w(幅) amp
pair("ear-fin",  "ひれ耳",  Curve::Vee,                  0.44, 0.80,      0.12, 0.070),
pair("vent-x2",  "はいき",  Curve::Teeth(2),             0.38, 0.76,      0.12, 0.045),
```

`off` は中心からの横位置で、単位は `w` と同じ（**その高さの半幅に対する比率**）。
0 で中央、0.8 前後で顔の端。半幅に比例するので細い顔では自動的に内側へ来る。
`off + w` が 1.0 を超えないようにしておくと安全
（番人は `parts::tests::paired_parts_are_pushed_to_the_side`）。

### 人間でないパーツ

素形の後半は**機械の顔**のためにある。生き物の顔は曲線だが、機械の顔は
直角・閉じた板・左右対の継ぎ目でできていて、弧と波をいくら足しても後者にはならない。

| 素形 | 形 | 例 |
|---|---|---|
| `Curve::Plate { taper }` | 閉じた台形の板（角が立つ） | 口のプレート・ボルト |
| `Curve::Bracket { down }` | 門型 ∏ / ∐ | 額の枠・アンテナ・ヒンジ |
| `Curve::Stroke` | 縦棒（横に寝ていない唯一の素形） | 縦の鼻筋・装甲の継ぎ目 |
| `Curve::Teeth(n)` | 角波 | 通気口・グリル・きざみ |
| `EyeForm::Wedge { .. }` | 角ばった四角形の目 | 兜のスリット |
| `EyeForm::Horn { up }` | 丸目の片側だけ角に引き出す | 角つきの吊り目 |

`Horn` を自分で書き直すときは **両端を尖らせないこと**。紡錘形にすると目が
「木の葉」になり、2 つ並べた瞬間に虫の翅にしか見えなくなる。

**角波・門型・板・輪・縦棒は `amp` を小さくしすぎないこと**。これらは縦の構造が
そのまま正体なので、潰れると別物になる（角波は一文字と、縦棒は「なし」と区別が
つかなくなる）。検証は「はみ出していないか」しか見ないので素通りする。
下限は `parts_whose_shape_is_vertical_do_not_collapse_at_real_size` が切っていて、
**髪のように bar にも描くカテゴリは 20pt の帯で評価される**ぶん厳しい。
帯に置くなら「山は少なく・高く」が原則（細かい歯を並べると灰色の塊になる）。

### カテゴリごと足す（眉・耳・アクセサリ…）

`LINES` に 1 つ足すだけ。線で描くものは全部この形に収まる。

```rust
pub const LINES: &[LineCategory] = &[
    LineCategory { id: "hair",  label: "髪", on_bar: true,  variants: HAIR },
    LineCategory { id: "brow",  label: "眉", on_bar: false, variants: BROW },  // ← 追加
    ...
];

pub const BROW: &[LinePart] = &[
    none("none", "なし"),
    line("flat", "一文字",  Curve::Arc, 0.64, 0.30, 0.010),
    // ...
];
```

`on_bar = false` にしておけば **bar のパネル線は dock の部分集合**になり、
bar は線を間引くという規則が構造的に通る。カテゴリ id は
`[[details]]` の `name` になるので `[a-z0-9-]+` にすること。

### 足したら

```sh
cargo test -p ccsessions-core face::builder
```

**全パーツ × 全輪郭の組み合わせが検証を通ることを総当たりで確かめる**
テストが入っている（`every_part_composes_into_a_valid_face` /
`every_outline_and_eye_pairing_is_valid` / `every_line_part_fits_on_every_outline`）。
はみ出す形を足すとここで落ちるので、数値を詰め直す手がかりになる。

**行を足してもバリエーション数のテストは落ちない**（下限だけを見ている）。
落ちるのは表を減らしたときだけ。

## 10. 困ったら

- **「書いたのに効かない」** → 綴り間違いはエラーになるようにしてある。
  `ccsessions face check` を見る
- **「目が顔から出る」（`eyes-outside-body`）** → `eyes.size` を小さくするか `eyes.v` で位置を変えるか、
  輪郭を広げる。あご周りが細い顔では特に起きやすい
- **「設定画面に出ない」** → `id` が既存の顔と衝突していないか（`id`）。
  `ccsessions face list` に出ているか確認する
- **スキーマの全体** → このファイルの §8。実装は `ccsessions-core/src/face/`
  （`spec.rs` の `ProblemCode` が検証規則の一覧、`parse.rs` が受け付ける書き方、
  `validate.rs` が規則の中身）
- **不変条件と設計の約束** → [`docs/invariants.md`](../docs/invariants.md)。
  なぜ顔をデータにしたのか・なぜ色を選ばせないのかは [`docs/adr/`](../docs/adr/README.md)
