# 0025 · 画面の文言は日英、診断は英語

採用 · 2026-07-29

## 文脈

README を英語主体（`README.md` / `README.ja.md`）にしたが、アプリ本体は日本語一色の
ままだった。設定画面もホバーカードも「作業中」「判断待ち」と出るので、英語話者に
渡せるのは README だけという状態になっていた。

数えると、画面に出る文言のうち**約 8 割は Rust 側で生まれて JSON で画面に渡っている**
（設定スキーマの label / help、顔パーツ名、状態名、検証メッセージ）。ブラウザ側だけの
切り替えでは成立しない。一方で全部を両対応にすると、一番数が多いのは顔パーツの
バリエーション名 194 個（「ジト目」「しもぶくれ」…）で、これは訳しても意味が薄い上に
**パーツを 1 行足すだけで済む**という `parts.rs` の性質を壊す。

## 決定

**文言を 3 つに分けて、それぞれ別の扱いにする。**

| 区分 | 扱い | 対象 |
|---|---|---|
| 画面の文言 | **日英両対応**（`language` 設定） | 設定画面・ビルダー・ホバーカードの状態名・`ccsessions list` の状態名 |
| 診断と検証 | **英語に一本化** | `doctor`・CLI のヘルプとエラー・顔の検証メッセージ・`config.toml` のコメント |
| 顔パーツ名 | **画面に出さない** | `parts.rs` の 194 個 |

- **対訳は型で持つ**（`lang::L { ja, en }`）。別ファイルの辞書にすると「辞書には
  有るが誰も引かない／引いているが辞書に無い」が生えるので、既存の const 表の
  `&'static str` を `L` に差し替える形にした。**片方の言語だけ書いた状態は
  コンパイルが通らない**ので、項目を足したときの訳し忘れがビルドで落ちる。
- **`auto` の解決は層ごと**。core は `lang::from_tag`（純関数）までしか持たず、
  タグの出どころは daemon が `NSLocale`、Web UI が `Accept-Language`、CLI が
  環境変数 `LANG`。**launchd 配下の daemon は `LANG` を継承しない**ので、
  daemon だけは NSLocale に訊く必要がある。
- **判断が付かなければ英語**。日本語だと確信できるときだけ日本語にする。

## 理由

**診断を英語に固定するのは、`doctor` の出力が issue に貼られるものだから。**
貼る人と読む人の言語が違ってよい方が都合がよく、切り替え機構に載せないぶん
辞書もテストの言語分岐も要らない。同じ理由で `config.toml` のコメントも英語にした
（設定ファイルは診断の出力と同じ「技術的な成果物」の側に置く）。

**パーツ名を消したのは、サムネイルがその形そのものだから。** 名前は情報を足して
いなかった。消したことで 194 個が翻訳の対象から外れ、「パーツを足すのに触るのは
`parts.rs` の 1 行だけ」が保たれる（訳が要ると、パーツを足すたびに英語も考える
ことになる）。id は `title` に入れてあるので、名指ししたいときはホバーで拾える。
**絵が空になる「なし」だけは文字を出す** — 選べることが分からなくなるため。

## 影響

- 設定に `language`（`auto` | `ja` | `en`）が 1 つ増えた。**画面側の変更はゼロ** —
  設定画面は `fields()` を列挙して描くので勝手に並ぶ（[ADR 0020](0020-single-settings-entrance.md)）。
- daemon への反映は既存の mtime ポーリング（`ConfigChanged` → `rebuild_and_reposition`
  → `hide_card`）に乗るので、**新しい配線は要らない**。次のホバーで新しい言語になる。
- ホバーカードの箱は文字幅の実測から作る（`card.rs`）ので、英語で長くなっても壊れない。
  ただし `ccsessions list` の桁揃えは固定幅なので、一番長い英語ラベル
  （"Agents running"）に合わせて 14 に広げた。
- `faces/*.toml` の `label_en` は以前から在ったが誰も読んでいなかった。
  `FaceSpec::display_label(lang)` が読むようになり、**組込み 4 顔は追加作業ゼロ**で
  英語名が出る。ビルダーが書き出す顔には `label_en` が無いので `label` に落ちる。
- `ProblemCode` の ASCII の code は元から locale 非依存なので、検証メッセージを
  英語にしても画面側の分岐は影響を受けない。
