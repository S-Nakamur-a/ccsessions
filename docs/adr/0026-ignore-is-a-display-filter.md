# 0026 · ignore は表示のフィルタ。枠を数える前に外す

採用 · 2026-07-30

## 文脈

定期作業用のディレクトリなど、走ってはいるが群れに出す必要のないセッションがある。
`config.toml` の `ignore` に条件を書いて一覧から外せるようにしたい。

セッションを表示のために絞り込んでいる場所は `store::list_live` の 1 つだけで、
呼び出し元は `ccsessions list` / `ccsessions doctor` / `ccsessionsd` の poller の
3 つ。`list_live` の中身は `list_in(dir).filter(is_live).take(max)` で、`take(max)` の
`max` は `max_sessions`（既定 12）。

## 決定

**フィルタは `store::list_live` の中、`is_live` の後ろ・`take(max)` の前に置く。**
戻り値を `LiveSessions { shown, ignored }` に変え、外した件数を呼び出し側へ返す。

**`sweep` には触らない。** ignore に当たったセッションのファイルはそのまま残り、
消えるのは今までどおり pid か TTL で死んだときだけ。

条件の照合対象は `cwd` / `name` / `title` の 3 つ。glob は自前で書く。

## 理由

- **`take(max)` の前でなければならない。** 後ろに置くと、ignore したセッションが
  枠 12 を食って生きているセッションを押し出す。これは
  [0008](0008-liveness-by-pid.md) が潰した「死んだセッションが枠を食う」不具合と
  同じ形で、番人も同じ（`dead_sessions_do_not_consume_the_max_slots` の隣に
  `ignored_sessions_do_not_consume_the_max_slots` を置いた）。
- **件数を別に返すのは、呼び出し側が引き算で求められないから。** 枠の前で外すので、
  1 件隠せば別のセッションが 1 件繰り上がる。「全部出したときとの差」は隠した件数に
  ならない。`ccsessions list` の「N 件を非表示」も `doctor` の `stale` 計数も、
  この数を直接受け取らないと嘘をつく。
- **呼び出し元 3 か所でフィルタする案は採らない。** 同じロジックが 3 つに散り、
  `take(max)` との順序を 3 回間違えられる。
- **`sweep` に効かせる案は採らない。** ignore は「見たくない」であって「死んだ」では
  ない。消してしまうと `--all` で戻すこともできず、hook が次に来た時点で作り直される
  だけの空振りになる。
- **ブランチ名での除外は入れない。** `Session` にも `HookPayload` にもブランチは
  無く、入れるには hook か daemon が cwd で `git` を叩くことになる。表示のフィルタに
  対して代償が大きい。worktree を畳みたいだけなら cwd の glob で足りる。
- **glob crate（`globset` / `glob` / `regex`）は足さない。** workspace の依存は
  `serde` / `serde_json` / `toml` / `libc` の 4 つだけで、版も実証済みの組み合わせに
  ピンしてある。数個の条件のために regex エンジンを引くのは釣り合わない。
  セグメント単位のマッチャは 100 行弱で、core の「純粋ロジックは全部テストできる」
  方針にそのまま乗る。
- **バックトラックは 2 ポインタ法**（`*` の戻り先を 1 つだけ覚える）で書く。素朴な
  再帰だと `a*a*a*a*b` のような条件が指数時間になり、**poller が毎 tick 踏む経路**に
  置く以上は避ける。番人は `a_pathological_glob_still_returns_quickly`。
- **相対パスをプロセスの `current_dir()` で解決する案は採らない。** `ccsessions list`
  を叩いたディレクトリで結果が変わり、cwd が `/` の常駐とは別の結果になる。同じ設定
  ファイルが 2 つの画面で違う挙動をするのは、フィルタとしていちばん困る壊れ方。
  代わりに gitignore と同じ「どの深さでも当たる連続セグメント列」にした。
- **glob には「配下も含む」を暗黙に足さない。** 足すと `*` と `**` の区別が消える。
  前方一致（glob を書かなかったとき）だけが配下を含む。唯一の例外は相対 glob の
  先頭で、`cron-*` は `**/cron-*` として扱う（相対の意味が「どの深さでも」なので）。
- **タイトルが無いセッションに `title:` の条件は当てない。** タイトルは transcript
  から拾うので取れないことがあり、当ててしまうとフィルタが気まぐれになる。

## 影響

- **`store::list_live` の戻り値が変わった。** `publish = false` で外部の利用者が
  いないので、互換シムは積まずに 3 か所の呼び出し元を直した。
- **`render_toml` に TOML エスケープが要るようになった。** `ignore` は任意の文字列を
  受ける最初の設定項目で、それまでのフィールドは enum か `is_valid_id` で検証済み
  だったため `"` が入る経路が無かった。エスケープを忘れると**保存は成功し、次の
  起動で `config::load` が `Err` を返して daemon が既定へ落ちる** ＝ ユーザには
  「設定が全部飛んだ」に見える。番人は
  `a_pattern_containing_quotes_survives_a_save_and_load_round_trip`。
- **設定ファイルの壊れた条件はその行だけ捨てて警告する。** 全体を `Err` にすると、
  打ち間違い 1 つで他の設定変更まで巻き添えで既定へ落ちる。一方 `config set` /
  Web UI は 1 件でも壊れていれば書かない — 人が今まさに打った指示なので、黙って
  一部を捨てるより即座に教える方が親切（[0016](0016-design-resolved-late.md) が
  `design` で採ったのと同じ非対称）。
- **`FieldKind::Lines` が増えた。** 設定の入口は Web UI ひとつ
  （[0020](0020-single-settings-entrance.md)）なので、新しい型を足すと
  `ui_cmd.rs` の match（Rust が網羅を強制する）と `app.js` の `fieldInput`
  （**こちらは黙って読み取り専用テキストに落ちる**）の両方を伸ばす必要がある。
- **demo モード（`make demo`）はフィルタの外側。** `flock::demo_sessions` が
  `list_live` を通らないため、フィルタの挙動は `make demo` では確かめられない。
- **条件は原文のまま保存する。** 展開後のパスを書き戻すと、`~/work` と書いた設定が
  保存のたびに `/Users/x/work` へ化ける。
- **`--all` は `max_sessions` の打ち切りも外す。** ignore と枠は別の絞り込みだが、
  枠を残すと「隠したものを見る唯一の手段」が、live が枠を超えた瞬間に機能しなくなる
  （しかも隠した側が新しいと、`--all` を付けたぶん実セッションの表示が減る）。
- **既知の限界: Unicode 正規化はしない。** 日本語ディレクトリ名を Web UI（IME は NFC）で
  条件に書き、APFS が cwd を NFD で返す場合、比較が外れて条件が黙って効かない可能性が
  ある。**未実測**。正規化は依存追加か自前実装が要り、「依存を増やさない」と釣り合わない。
  実際に踏んだら、まず cwd がどちらで届くかを測ってから直す。
- **壊れた条件は設定の往復で失われる。** `load` が壊れた行を捨てるので、Web UI から
  無関係な項目を 1 つ変えて保存すると、手書きの壊れた行は黙って消える（警告は
  `ccsessions ui` の stderr にしか出ない）。壊れた行を保持する道は「その行だけ捨てる」
  という上の決定と衝突するので採らない。
