# 0016 · `design` の実在検証はレジストリ解決時に行う

採用 · 2026-07-26

## 文脈

顔がデータになったので（[0014](0014-faces-as-data.md)）、`config.toml` の `design` に
書ける値はもう固定の enum ではない。ユーザ顔ファイルが置かれているかどうかは、
設定をパースする時点では分からない。

## 決定

- **`config::load` は `design` の実在を検証しない。** 見るのは形
  （`[a-z0-9-]+`、先頭は英数字、32 文字以内）だけ。
- 実在の判定は顔レジストリの解決時（`face::Registry::resolve`）に行い、
  **未知の id は `Err` ではなく `egg` へのフォールバック + ログ**にする。
- ただし **`ccsessions config set design <id>` と Web UI の保存は実在チェックをする**。
  そこは今まさに人が選んだ明示的な指示なので、打ち間違いを黙って受けるより
  即座に教える方が親切。

## 理由

読み込み時に `Err` にすると、顔ファイルを消しただけで daemon が設定を丸ごと
last-good に巻き戻す。表示ツールとしては「知らない顔だったので egg にした」と
ログに残して動き続ける方が正しい。

## 影響

`Config.design` は `String`。組込みの選択肢一覧（`config.toml` のコメントに埋める値）
はレジストリから動的に作る。実際に使える顔の一覧は `ccsessions face list` が見せる。
