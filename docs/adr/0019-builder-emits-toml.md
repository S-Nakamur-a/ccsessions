# 0019 · ビルダーは TOML テキストを唯一の中間形にする

採用 · 2026-07-27

## 文脈

パーツを選んで顔を作るキャラクタービルダーを足した。ビルダーは画面にプレビューを
出しつつ、最終的にファイルを保存する。

## 決定

**ビルダーが出すのは今までどおり `faces/*.toml`** で、しかも**生成した TOML テキストを
唯一の中間形にする**。

```
Draft → TOML テキスト → parse::parse → FaceSpec → プレビュー / 検証
```

`FaceSpec` を直接組んで「ついでに TOML も書き出す」形にはしない。

## 理由

2 経路にすると、座標の丸めや書き出し漏れで**画面で見た顔と保存される顔が別物になる**
（しかも保存するまで誰も気づかない）。同じ理由でプレビューは JS で描き直さず、
`face::svg` の出力をそのまま貼る（[0018](0018-svg-preview.md)）。

番人は `builder::tests::the_generated_toml_parses_back_into_the_same_face`。

## 影響

- **ビルダーは「顔の形式」を増やさない。** 手で書いた顔とビルダーが作った顔は
  同じスキーマで、daemon から見て区別が無い。
- **どの組み合わせでも検証を通る**ことを 3 つの仕掛けで支えている。
  パネル線の幅を輪郭の断面に比例させる / 目は**検証器そのものを使って**収まるまで
  縮める / bar のパネル線を dock の部分集合に縛る。総当たりのテストがこれを守るので、
  パーツを足したら必ず走らせる。
- **左右 1 対のパーツは、右を計算して鏡像を取る。** 左右を別々に計算すると丸めで
  1 単位ずれ、生き物が傾いて見える。端への寄せも幅と同じく半幅に比例させる
  （比例させないと細い顔で耳が輪郭からはみ出す）。
- **その顔専用のパーツは表に置かない。** 他の輪郭に載せると比率が合わず浮く。
- **バリエーション数のテストは下限しか見ない。** 個数の等値で固定すると、行を
  足すたびに落ち、「1 行足すだけ」という設計そのものを罰することになる。
