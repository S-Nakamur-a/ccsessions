# 0007 · 書き込み先は名指しされたときだけ。追記マージのみ

採用 · 2026-07-25 — 改訂 2026-07-28（書き込み先を推測しない・確認を挟む）
— **2026-07-29 に [0021](0021-distribution.md) が置き換えた。実装は消えている。**

> **この ADR が守っていた `install-hooks` / `uninstall-hooks` はもう無い。**
> hook の配線は Claude Code プラグインに移り、ccsessions は `settings.json` を
> 一切書かなくなった。ここに書いてある制約（推測しない・追記のみ・バックアップ・
> 同意・冪等）は**そのとき何が危険だったかの記録**として残す。
>
> **もう一度 settings.json を書くコードを入れるなら、まずこの ADR を通しで読むこと。**
> 5 つの制約は「1 つ落とすと他人の本番ファイルが壊れる」という理由で全部要る。

## 文脈

Claude Code の設定は他ツールの hook が同居する**本番ファイル**で、しかも
**1 つとは限らない** ―― ユーザ全体（`~/.claude/settings.json`）・プロジェクト
（`<repo>/.claude/settings.json`）・ローカル（`*.local.json`）が併存し、
enterprise の managed settings やプラグイン由来の hook もある。ユーザは後から
移すことも分割することもある。

つまり ccsessions 側から「たぶんこのファイルだろう」と決め打ちできる根拠が無い。
決め打ちした結果は 2 通りとも悪い ―― 意図しないファイルを書き換えるか、
「消したはずなのに消えていない」（別ファイルに残っている）になる。

## 決定

**書き込み先は ccsessions が推測しない。名指しされたファイルにだけ責任を持つ。**
`install-hooks` / `uninstall-hooks` は引数の有無で役割が変わる。

| | 引数なし | `<path>` あり |
|---|---|---|
| `install-hooks` | 貼るべき JSON 断片と置き場所を出すだけ（**読みも書きもしない**） | そのファイルにだけ追記する |
| `uninstall-hooks` | 既知の settings ファイルを走査して**在り処を報告**する（読むだけ） | そのファイルからだけ取り除く |

`<path>` を伴う書き込みは次を守る。

- **同意なしに書かない。** 何をどのイベントに足す／消すかを見せて y/N を聞く。
  `--yes` で省ける。**stdin が端末でなく確認を取れない場合は書かずに exit 1。**
- **`~/.claude` の外を指したら警告する。** プロジェクトの設定はリポジトリに
  入るので、そこへ書くと `current_exe()` の絶対パスがチームに配られる。
- **既存エントリを変更しない**（自分のエントリへの `timeout` 追加を除く。
  [0006](0006-hook-timeout.md) 参照）。追記マージだけを行う。
- 書き込み前に `<path>.ccsessions-bak.<epoch>` へバックアップを取る。
- **冪等**。2 回実行しても 2 重に入らない。
- 自分のエントリの判定は command 文字列に `ccsessions hook` を含むかどうか
  （`settings_json::MARKER`）。**イベント名では判定しない** ―― 旧バージョンが
  書いた `PreToolUse` のエントリも拾えるようにするため（[0005](0005-subscribed-hook-events.md)）。

**読む側は逆に、分割に追随する。** `known_settings_paths()` がユーザ全体 →
カレントディレクトリ → その祖先の順に候補を列挙し、`doctor` と引数なしの
`uninstall-hooks` が全部を走査する。書くのは 1 ファイル、読むのは全部 ―― この
非対称は意図的で、「入れたときとは別のファイルに残っている」に人が気づける
唯一の手段がこの走査だから。

## 理由

はじめは `--settings` 未指定なら `~/.claude/settings.json` を既定にしていた。
これは 2 つの意味で危うかった。

1. **黙って書いていた。** 差分を見せる `--dry-run` はあったが、知っている人しか
   使わない＝実質「何も聞かずに書く」が既定だった。rustup が `PATH` を触る前に
   内容を見せて聞き、`--no-modify-path` も用意しているのと同じ形に揃える。
2. **戻せる保証が単一ファイル前提だった。** ユーザが移した・分割した後の
   `uninstall-hooks` は「何も見つからない」と言って exit 0 する ―― 嘘ではないが、
   ユーザが期待する「消えた」とは違う。名指しにすれば約束が「あなたが指した
   このファイルについて」に縮み、正直になる。

「そもそも一切書かず、貼り方を教えるだけにする」も検討した。採らなかったのは、
既存の `hooks` オブジェクトへ 10 イベント分をマージする手作業が現実的でなく、
間違えたときに壊れるのが**他ツールの hook** だから。書く機能は残す価値がある
―― ただし**行き先を人が決めたときだけ**。

## 影響

- **テストは本物の `~/.claude/settings.json` に絶対に触らない。** tempdir に
  埋め込みフィクスチャを書き、そのパスを位置引数で渡す。本物をコピーして使うと、
  ccsessions を導入した瞬間に冪等性テストが壊れる（実際に踏んだ）。走査を伴う
  コマンドのテストは `HOME` とカレントディレクトリごと tempdir に閉じる。
- **CI やスクリプトから入れるときは `<path> --yes` の両方が要る。** 片方でも
  欠けると何も書かずに終わる（黙って書かれるより良い、という選択）。
- 同じ規律を `ccsessions ui` のテストにも適用している（`--config` / `--faces-dir`）。
- **走査で「無い」と言えるのは既知のファイルの範囲だけ。** enterprise の
  managed settings とプラグイン由来の hook は見えない。README の既知の制限に書く。
- 配布時は、settings ファイルを触らずに済む Claude Code プラグインを主導線にする
  （[0021](0021-distribution.md)）。formula に settings を触らせてはいけない。
