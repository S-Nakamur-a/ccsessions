# 0010 · 狭い帯では要素を体に重ねて集約する

採用 · 2026-07-25 / メニューバー高への一般化 2026-07-26

## 文脈

bar 配置の窓はメニューバーの中に収めなければならない。**窓は自分の矩形ぶんだけ
下のクリックを奪う**ので、帯がメニューバーより下へ伸びると、その面積ぶん
メニューバーの通常操作が壊れる。

使える高さは機種依存で、**ノッチ機は 33pt、非ノッチ画面（外部モニタ・Air・旧機種）は
24pt しかない**。しかも `NSScreen::mainScreen` はフォーカス追従なので、
外部モニタにフォーカスを移すだけで後者に切り替わる。「他人の Mac の問題」ではない。

元のデザインは体の上に吹き出し（+22pt）を置き、バッジを体の外へ垂らし、
グリフを体の右上に浮かせる。そのままでは 33pt にも入らない。

## 決定

**縮小ではなく「重ねて集約」で詰める。** 段階は 3 つ（`layout::bar_fit`）。

| 使える高さ | やること |
|---|---|
| `体 + 12pt` 以上 | そのまま（グリフを体の外へ浮かせる） |
| `体 + 2pt` 以上 | **グリフを体に重ねる**。余った高さを headroom にする |
| それ未満 | 体そのものを縮める（想定外に低い帯への保険） |

bar では最初から次の 2 つも効いている。

- **吹き出しと `z` を出さない。** どちらもグリフ（`!` / `z`）と同じ情報なので、
  狭い帯ではグリフ 1 個に集約する（dock は元デザインどおり全部出す）。
- **バッジを体の外へ垂らさず右下に重ねる。**

## 理由

全体を等倍縮小する案は却下した。24pt 環境では 0.75 倍になり、目が 2pt 台になって
**状態が読めなくなる**＝このプロジェクトの存在意義が消える。体すら入らない
段階 3 の保険としてだけ残す。

「狭いところでは要素を体に集約する」はこの設計が 3 回続けて採ってきた判断で、
一貫している。

## 影響

- **アニメの振れ幅を絞る分母は「縦アニメの最大振幅」であって headroom の既定値では
  ない。** 段階 2 ではグリフを体に重ねてあるので、余地は丸ごとアニメが使える。
  「4pt 空いていれば 4pt 跳べる」が正しい対応で、24pt でも倍率は 1.0 ＝ 見た目の
  劣化が無い。既定の headroom（12）で割ると 24pt で 1/3 になり、bob の振幅が 0.67pt
  ＝事実上の静止になってしまう。
- `show_glyphs` を実装してある。設定・README に存在して効かない状態が一番よくない
  （実際そうなっていた時期がある）ので、段階 3 の逃げ道としても機能させる。
- 番人は `layout.rs` の
  `every_face_fits_inside_every_supported_menu_bar`（全顔 × {24, 33}）と
  `the_glyph_box_stays_inside_the_window_even_mid_animation`。前者は上限しか
  見ないので、絞り方そのものは
  `the_animation_is_scaled_to_exactly_the_room_above_the_body` が押さえる。
- 顔が名乗れる bar の体の高さには上限がある（[0017](0017-face-bar-height-limit.md)）。
