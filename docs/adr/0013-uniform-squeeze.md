# 0013 · 群れの縮小は一様でなければならない

採用 · 2026-07-26

## 文脈

生き物は横一列に並ぶので、セッションが増えるほど帯が広がる。使える幅
（ノッチ右の空き、または dock パネルの内寸）に収まらなくなったとき、
逃がすより縮めた方が安全な場面がある（[0012](0012-notch-avoidance.md)）。

## 決定

縮め方は**一様な縮小だけ**にする（`layout::Squeeze`）。体・間隔・余白・付属パーツ・
アニメの振れ幅すべてに同じ倍率を掛ける。

倍率は 3 段階。「収まっているなら何もしない」→「基準倍率 0.75」→「収まる倍率まで
（下限 0.55）」。下限まで縮めても入らないなら**縮小を諦めて**
[0012](0012-notch-avoidance.md) の退避に任せる。判読できない粒まで縮めるくらいなら、
大きく出して重なる方がまし。

## 理由

一様でないと 2 通りに静かに壊れる。

1. `layout::squeeze` は**幅が倍率に比例する**前提で「収まる倍率 = 使える幅 ÷ 自然幅」を
   解いている。余白だけ据え置く／条件で足し引きすると、縮めたのにはみ出す。
2. 縦の不変条件（メニューバーに収まる・グリフがアニメの頂点で切れない）は、
   不等式の両辺が同じだけ縮むから保たれる。体だけ縮めると余白を突き抜ける。

## 影響

- `creature.rs` が theme や `FaceSpec` から読む pt 値には**もれなく倍率を掛ける**こと。
  `FaceSpec::eye` は体が等倍である前提の pt を返すので、掛け忘れると縮んだ体から
  目がはみ出す。
- 唯一の例外は dock のラベル 2 段（名前・経過時間）とバッジ。これらは縮めると
  読めないので**省く**。省いたぶんは高さ・幅から落ちるので、比例の前提は崩れない。
- 番人は `a_compact_flock_still_fits_inside_every_supported_menu_bar` と
  `squeezing_scales_the_whole_layout_uniformly`。
