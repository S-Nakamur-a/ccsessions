# 0014 · 顔は `faces/*.toml` のデータで定義する

採用 · 2026-07-26

## 文脈

顔（生き物のデザイン）を 1 つ足すのに、以前は 6 ファイル・12 か所を触る必要があった
（enum の variant、選択肢の文字列、`as_str`/`from_str` の match、寸法・目・輪郭・
線画の関数、メニューの tag 分岐、README）。外部の人が PR を出すには Rust と objc2 と
全体構造の理解が要る。

## 決定

顔を TOML のデータにする。組込みは `faces/*.toml` を `include_str!`、ユーザ顔は
`~/.config/ccsessions/faces/*.toml` から読む。**Rust を書かずに、再ビルドもせずに
顔を足せる**（daemon が顔ディレクトリの変更をポーリングしている）。

- 座標はすべて体の矩形に対する **0..1 の比率・左下原点・y は上向き**（CALayer と同じ）。
  1 つの記述で bar と dock の 2 サイズを賄うため。CSS から写すときは y を反転する。
- 輪郭は **SVG の `d` 属性サブセット**（`M` / `L` / `C` / `Z` の絶対座標）で書く。
  ベクタツールからそのままコピーできる。角丸長方形系のためには
  `kind = "corners"`（CSS の `border-radius` 相当）も残す。
- `half = true` なら右半分だけ書けばよい。左半分は鏡像で自動生成され、対称性が
  テストで保証される。

却下:

- **Rust のまま 1 ファイルに集約** — enum を消せないので match が残り、
  「Rust を書かずに」が達成できない。
- **SVG ファイルの丸ごとインポート** — `transform` / `viewBox` / グループ / 相対座標 /
  円弧コマンドまで面倒を見ることになり割に合わない。実際に使うのは直線と 3 次ベジェの
  2 種だけなので、パス文字列だけ受け取れば表現力は足りる。
- **各顔を dylib プラグインに** — 署名・ABI・クラッシュ耐性の問題を丸ごと抱える。

## 影響

- **`ccsessionsd/src/theme.rs` に顔ごとの分岐を戻さない。** 形・目・線画・寸法は
  `FaceSpec` が持ち、`theme.rs` には全部の顔に共通の定数だけを置く。
- 検証（輪郭が閉じている・目とパネル線が輪郭の内側・bar の高さ制限など）は
  `ccsessions-core/src/face/validate.rs` に集約し、CLI と daemon の両方から使う。
  **組込み顔は全ファイルをループしてテストが検証を通す**ので、投稿者は TOML を
  1 つ置くだけで CI がはみ出しや高さ超過を指摘してくれる。
- **ユーザ顔が壊れていてもプロセスを落とさない。** 問題を stderr に列挙してその顔だけ
  無視し、`design` が無効な顔を指していれば `egg` へ落とす。
- 既存 5 種の見た目は `face/golden.rs` が数値で固定してあるので、解決ロジックを
  触ったら必ず走らせる。
